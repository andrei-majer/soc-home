01

Use case

why this exists

$ soc@home:~# whoami

End-to-end ownership of the same tooling SOC analysts and detection engineers use in production. Real internet traffic, real alerts, real incidents — and the operational discipline (IaC, drift detection, disaster recovery) to keep all of it healthy.

Concretely, the lab is used to detect intrusion attempts at multiple layers, investigate them with full-packet capture and endpoint forensics, enrich findings against curated threat intelligence, share back what's seen so the intel loop is bidirectional, and respond by dropping confirmed offenders at the network edge within minutes — without manual intervention.

DNS

Operations

infrastructure as code

IaC repository

  • /opt/soc-ansible/ on .120 · public mirror andrei-majer/soc-home
  • 8 roles (common, suricata, elk, wazuh-manager, misp, opencti, canary, tpot, openwrt)
  • 7 ops playbooks (health-check, ti-health, rule-update, es-cleanup, cert-renew, backup, restart-services)
  • Vault-encrypted per-host secrets
  • ansible-lint clean at production profile
  • Idempotent — 0 changed / 0 failed on clean re-converge

Daily loop

  • Morning health-check: service liveness, MISP rule age, OpenCTI/RabbitMQ flow
  • Freshness FAIL gates on eve.json and conn.log
  • Disk WARN/FAIL thresholds (80% / 90%) on every host including router
  • Suricata loaded-rule count via suricatasc -c dump-counters
  • Wazuh agent count drift assert
  • Canary services + listening port count

Disaster recovery

  • Self-remediating disk-alert — vacuum + gzip at 92%, ntfy push
  • journald capped at 200 MB cluster-wide
  • Router-side soc-watchdog — independent monitor that survives full hypervisor loss
  • Monthly backups — Ansible role + Windows OneDrive sync
  • git-bundle snapshots of the IaC repo itself with vault password
  • Proven in a real outage (2026-05-31 disk-full incident → hardening now in IaC)

Bootstrap & provisioning

  • Packer + Vagrant — base Debian image bake
  • deploy.ps1 — Windows-side orchestrator
  • Repacked Velociraptor MSI for zero-touch Windows agent enrolment
  • VM tuning codified — virtio NIC + storage; HVCI/VBS/AppGuard audit-and-disable workflow for Windows hosts
  • Runbooks for what Ansible can't reach — .13 Windows workstation + .15 Ubuntu hypervisor (Secure Boot + MOK-signed VBox modules)
06

What makes this different from a tutorial lab

load-bearing details
Closed-loop intel
Detection → sighting → enrichment → rule update completes without manual touch. Suricata pushes sightings into MISP; OpenCTI pulls MISP and enriches; TAXII ships indicators back to Wazuh; Wazuh escalates matches at severity 10.
Edge enforcement
Active response lives on the router, not on a host that could go down. BanIP holds the line whether the SIEM is up or not — and the SIEM only adds to it, never depends on it.
DR-tested IaC
A real disk-full outage exposed gaps; the resulting hardening (self-remediating disk-alert, journald caps, router watchdog) is now committed. IaC isn't a slide — it's how the lab gets restored.
Independent watchdog
Alerting that depends on the alerting host is not alerting. The router runs a 5-min cron that pings the hypervisor and IDS host and pushes ntfy on outage — the only path that survives a full VM-stack loss.
Internal canary
fs1 looks like a real fileserver: real Samba, plausible share names, plausible filenames. Any touch is a high-confidence signal — distinct from external honeypots that just measure internet noise.
Quiet by design
VM-level tuning (virtio NIC + storage, snapshot consolidation, CPU pinning) plus an automated nightly sleep/wake cycle keep the full stack lean on a single i7-9700K workstation — near-silent, 24/7.
